Problem. "What mode does this attempt grade under" is decided twice with different predicates — the next-task decision weighs dueAt and hasAttemptToday; the submit pipeline re-derives mode from mastery alone — so any Kuasai submission that was never a served review (replay, late offline sync) still fires SM-2, including the downgrade-to-Lancar rule the schedule never requested.

Solution. One classification module — attemptMode(mastery, {now, dueAt, hasAttemptToday}) — called by both; the deeper variant echoes the served kind through the outbox onto the attempt row so grading follows what was actually served.

  • locality: review policy encoded once
  • leverage: one classifier, next-task + grading
  • testability: the predicate is tested against both callers' fixtures
ADR-worthy: does grading trust the served task record, or re-derive from mastery? Pick one owner and write it down.
